# Экспериментальный контракт словарного пакета

Версия упаковки `package_format` равна 1 для плоской атрибуции или 2 для компактной. Независимые от упаковки поля `schema_version` и SQLite `user_version` равны 1 или 2 и должны совпадать. Пакет содержит `dictionary.sqlite` и `manifest.json`. Staging хранит сырой контекст, источники и решения. Поставляемая база содержит допустимые статьи, значения, переводы, формы, примеры и переводы примеров. Личные данные находятся в отдельной базе Room.

## Экспериментальная схема 2

V1 остаётся форматом экспорта по умолчанию и читается Android без миграции. Для V2 задайте `--schema-version 2`. V2 добавляет `lexical_metadata` и индексы для чтения статьи и предварительного просмотра перевода. Один элемент метаданных относится ровно к одному объекту:

| Объект | Допустимые элементы |
| --- | --- |
| Статья | IPA, вариант произношения, регион |
| Значение | Определение, исходная глосса, регистр, регион, CEFR |
| Словоформа | Грамматическая характеристика |

В каждой строке есть вид, текст, язык и ссылка на атрибуцию. Определение, глосса и одобренный перевод хранятся раздельно. Дополнительная строка попадает в пакет, если для неё есть собственное решение о правах и её родитель уже разрешён к экспорту. Staging-таблица описана константой `STAGING_METADATA` в `release_package.py`. Для реального наполнения нужны подтверждённая связь с объектом и свидетельство происхождения. Экспорт V2 без дополнительных данных допустим, если в ядре есть пригодные статьи.

## Валидация

В манифест входят версия корпуса, алгоритм нормализации, версия Unicode, направления EN ↔ RU, числа строк по таблицам, контрольная сумма SQLite, снимки, ссылки на условия и атрибуция по каждому включённому элементу. Набор таблиц, индексы и точная схема проверяются по SQLite, как и `integrity_check`, внешние ключи, идентификаторы, числа строк и ссылки атрибуции. Пакет с нулём одобренных статей отклоняется. Экспорт требует вручную одобренного перевода и отдельного clearance у статьи, значения, исходной глоссы и перевода. Файл SQLite и манифест валидируются вместе. SHA-256 проверяет совпадение файлов. Для подлинности будущего обновления потребуется доверенная подпись или канал поставки. Проверка установленного пакета не заменяет проверку исходного staging при экспорте.

Лимиты экспериментальной версии составляют 64 МиБ для манифеста и 256 МиБ для SQLite. Для большого реального выпуска надо измерить пиковую память парсера. В перспективе следует проверить подписанный манифест, заранее известный ключ приложения, откат к последнему проверенному выпуску и обработку устаревшей подписанной версии. Контракт V2 ожидает согласования.

```text
python research/prototypes/sqlite_poc/release_package.py rights STAGING RIGHTS.jsonl
python research/prototypes/sqlite_poc/release_package.py bind REGISTRY.sqlite BINDINGS.jsonl
python research/prototypes/sqlite_poc/release_package.py export STAGING REGISTRY.sqlite NEW_PACKAGE_DIR CORPUS_VERSION
python research/prototypes/sqlite_poc/release_package.py validate PACKAGE_DIR
```

CLI принимает базы и каталоги пакетов под `research/data/processed/`, решения под `research/data/review/`. Используйте новые выходные пути. Повторный экспорт в разные каталоги дал одинаковый результат на искусственном наборе в одной среде. Межверсионная байтовая идентичность SQLite в контракт не входит.

## Экспериментальный компактный манифест

Опция `export --compact` сохраняет SQLite V1/V2 с теми же ссылками, а манифест получает `package_format=2`. В `policies` хранится список общих политик. Каждая ссылка `attributions` кодируется как `[индекс политики, исходный локатор, модификация]`. Политика содержит `source`, `snapshot`, `source_url`, `license_id`, `terms_url` и `attribution`. Python и Android сверяют идентификатор полной записи по каноническому ASCII JSON с отсортированными ключами, проверяют список источников и отклоняют повторяющиеся ключи. Android хранит типизированную ссылку на общую политику у каждого локатора. Файл новой версии проверяется перед сменой активного указателя. Обычный экспорт сохраняет `package_format=1`. [Исходные настольные измерения](CORPUS_ENRICHMENT.md#упаковка-и-производительность)

## Постоянные идентификаторы

Локальный реестр версии 1 хранит строки `kind`, `snapshot`, `local_id`, `persistent_id`, `reason`. Импорт JSONL при продолжении известного объекта принимает дополнительно `previous` из двух полей, предыдущего SHA и предыдущего локального ID. Постоянный UUID задаётся при первом подтверждении. Привязка в новом снимке требует явной ссылки на подтверждённого предшественника. Второй объект с тем же UUID в одном снимке отклоняется. Исходный ID, написание, язык, POS, смысл и происхождение используются как признаки кандидатов, а не как команда переноса. Перестановка строк сама по себе ничего не меняет в реестре. Удалённые записи остаются в истории. Для разделения и слияния смыслов следует явно выбрать продолжение или создать новые UUID. Отдельное хранение направленных связей split/merge и перенос пользовательских ссылок остаются открытыми. Существующие экспериментальные базы сохраняют локальные идентификаторы.

Хранение UUID в TEXT выбрано для проверки прототипа. BLOB и целочисленные FK с отдельным постоянным ключом следует сравнить на одинаковом объёме корпуса. Схема и упаковка реального словаря требуют утверждения.

## Предложение для первого доверенного выпуска

Для первого корпуса предпочтителен пакет внутри APK, подписанного ключом приложения. До включения корпуса владелец утверждает редактуру, права и атрибуцию, устойчивые ID и объём. Клиенту потребуется отдельный разрешённый release asset, а установленный кандидат проходит существующие проверки SHA-256, схемы и связей перед активацией. В текущей сборке этот путь существует для debug-ассетов.

При отдельной автономной поставке предлагается подписывать точные байты ограниченного по размеру манифеста. Доверенный публичный ключ встроен в приложение. Подпись связывает версию корпуса, целевые форматы и SHA-256 SQLite. Перед активацией проверяются подпись, SHA-256 и последовательность выпусков. Файлы-кандидаты пишутся в новый каталог, проходят валидацию, затем меняется атомарный указатель. Для восстановления хранится последняя проверенная версия с отдельной меткой успешной активации. Политика отката должна отличать восстановление после сбоя от установки более старого выпуска. Room остаётся в отдельном файле, а сохранения продолжают ссылаться на постоянные ID. Внешняя установка и проверка подписи манифеста остаются предложением для согласования.

## Вложенный контекст FreeDict

Редакторская задача хранит исходный смысл перевода отдельно от владельца определения. Для определения фиксируются собственные ID смысла, локатор, язык, снимок и права. Если у источника два или более возможных дочерних узла, автоматическая подсказка контекста отсутствует. Локальный аудит подтвердил 200 из 200 ключей существующей очереди. У всех 200 определение принадлежит прямому дочернему узлу.

SQLite V2 поддерживает необязательное расширение манифеста `sense_context` версии 1. Ключ — постоянный UUID переводного смысла. Строка содержит `relationship=direct-child`, английский `text`, `language=en` и отдельные ссылки `owner` и `definition` на атрибуцию исходного дочернего узла и определения. Манифест хранит принадлежность через локаторы и снимок, а SQLite и прежние UUID остаются совместимыми. Android и Python проверяют существование переводного смысла, совпадение источника и SHA снимка и точные вложенные локаторы. Android отображает связь как «Контекст источника» внутри переводного смысла. Обратный поиск и сохранение продолжают использовать его UUID.

Команда `release_package.py context STAGING CONTEXT_DECISIONS.jsonl` принимает явные решения по полям `parent_id`, `snapshot`, `definition_locator`, `reviewer`, `reason`, `decision=approved`, `method=human`. Решения применяются транзакционно. Два разных решения для одного переводного смысла конфликтуют. Экспорт требует допущенного переводного смысла и отдельного clearance для владельца и определения. Реальные решения по контексту пока отсутствуют.

Для дополнения многословных единиц используйте отдельные страты на том же SHA FreeDict. `pos='phraseologicalUnit'` задаёт источник фразеологических кандидатов. `pos='v' AND instr(search_key,' ')>0` задаёт кандидатов в многословные глаголы для ручной классификации фразовых глаголов. В каждой страте сначала выбирайте статьи с явно помеченным русским кандидатом, сортируйте по SHA-256 от фиксированного seed и локатора и сохраняйте отдельные исходные смыслы и POS. Зафиксируйте квоту и seed до просмотра и храните результат отдельно от частотной выборки. Ранг означает воспроизводимый порядок просмотра.
