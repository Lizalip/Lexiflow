# Работа с LexiFlow

При определении требований учитывайте паспорт стартап-проекта, актуальный HANDOFF и текущую задачу владельца. Исследовательские выводы по корпусу предварительные. Расширение объёма и подключение данных требуют согласования.

- Клиент пишется на Java с Android SDK, XML и Material Components. Нижняя граница поддержки — API 29.
- Представление находится в `app/src/main/java/app/lexiflow/ui`, локальный источник данных — в `data`. Строки и цвета размещайте в ресурсах.
- Сохраняйте автономность. Не добавляйте вымышленные статьи, Room-схему или ETL до утверждения модели. Сохраняйте исходные ноутбуки и исследовательские отчёты.
- После значимых изменений запускайте Gradle Wrapper. Основные задачи — `:app:assembleDebug`, `:app:testDebugUnitTest`, `:app:lintDebug`. Для Espresso нужен эмулятор или устройство.
- В отчёте различайте сборку тестового APK и выполнение тестов. Фиксируйте точную причину пропущенной проверки.
- Не делайте автоматические commit или push.

## Стадии и источники

- Паспорт задаёт требования полного продукта. HANDOFF определяет последовательность реализации, текущая задача владельца — объём изменения. Переход к следующей стадии требует явной приёмки предыдущей.
- Первая стадия ориентирована на автономную пару EN ↔ RU. Метрики корпуса, размера и скорости приводите с указанием источника, выборки и метода. Плановые показатели паспорта отмечайте как цели.
- Различайте исходную статью и личные дополнения пользователя. Предложения по источникам, лицензиям, схеме и ETL фиксируйте как открытые решения до согласования. Примеры, переводы и атрибуцию берите из проверенных материалов.
- Перед изменениями сверяйте рабочее дерево, индекс и историю. Сохраняйте локальную работу пользователя, включая подготовленные изменения. Для материалов, отсутствующих в рабочей копии, используйте чтение через `git show <ref>:<path>`.
- В журнале прогресса отдельно фиксируйте реализацию, результаты проверок и условия, мешающие приёмке. Обновление зависимостей согласуйте отдельно.
