Срез относится к локальной рабочей копии Android-фундамента. Паспорт задаёт требования продукта, а HANDOFF от 24 ноября определяет границы стадий. Приёмка первой стадии ещё предстоит.

## План отдельной очистки Git

1. Сохранить текущую Windows-копию вместе с незакоммиченным Android-проектом и индексом. В WSL определить фактический путь окружения и сделать резервную копию вне репозитория с сохранением прав и символьных ссылок. Проверить, что копия читается, а исходный `research/env/bin/python` запускается. Наличие и работоспособность WSL-копии в этой задаче не проверялись.
2. Для отдельной согласованной операции подготовить независимый чистый клон актуальной основной ветки в **файловой системе Linux**. Имена с двоеточием представимы там как обычные файлы. Рабочие деревья с приложением и действующим окружением для этой операции не использовать.
3. В чистом клоне проверить базовую ревизию и пустой индекс изменений. Внести только проверенные правила исключений. Сверить списки `git ls-files -- research/env/` и `git ls-files -- '*:Zone.Identifier'`. Выполнить предпросмотр `git rm -r -n --cached -- research/env/` и `git rm -n --cached -- '*:Zone.Identifier'`. Для снимка `ac1329e2` ожидаются 18 606 и 4 пути соответственно.
4. Только после согласования, в том же изолированном клоне повторить проверенные команды без `-n`, сохранив `--cached`. Просмотреть `git diff --cached --name-status`: допустимы правила исключений и только согласованные удаления из индекса. Проверить наличие файлов на диске, отслеживание ноутбука, обоих отчётов, HANDOFF и `requirements.txt`. Решение о коммите принять отдельно.
5. Перед получением будущего коммита очистки в рабочей WSL-копии сохранить окружение вне рабочей директории: обновление другой копии Git может удалить ранее отслеживаемые файлы с диска. После согласованного обновления восстановить окружение по исходному пути, проверить интерпретатор и `git check-ignore -v research/env/bin/python`. Предыдущие коммиты продолжат содержать окружение.
