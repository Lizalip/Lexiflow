## Отбор и метаданные

`ranked` сохранён как baseline. `frequency` использует тот же фильтр пригодности для выбора написаний. Приоритет отдают засвидетельствованным употреблениям, затем ожидаемой сложности проверки, полноте (контекст и IPA), числу пригодных смыслов и POS для разрешения равенств. После выбора импортируются все английские записи выбранного нормализованного заголовка. Оценки наполненности и сложности остаются эвристиками. В FreeDict приоритет строится по явному языку структурированного перевода, контексту, POS и числу вариантов на узле. Релизный статус у этих признаков отсутствует.

| Написаний | Совпадений между отборами | Статьи baseline → частотный | Значения baseline → частотный | Написания с несколькими POS в частотном | Покрытие диагностики baseline → частотный |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 100 | 2 | 100 → 247 | 258 → 875 | 76 | 2 → 1 |
| 1 000 | 179 | 1 000 → 2 099 | 2 536 → 7 407 | 611 | 2 → 8 |
| 5 000 | 2 556 | 5 000 → 8 315 | 13 162 → 23 993 | 1 847 | 8 → 9 |

Все 5 000 частотных написаний имели положительный счётчик. При этом пропали многословные единицы. Для покрытия выражений потребуется отдельная страта или собственный частотный источник фраз. Объём полисемии и POS вырос также за счёт повторного чтения всех статей выбранного написания. Корректность переводов по этой таблице оценить нельзя.

FreeDict записывает исходный порядок и вложенность смыслов, локаторы из распаковки и контрольную сумму архива. Узлы сохраняются раздельно. Структурированный русский кандидат записывается в проверяемый вход `source_gloss` с собственным локатором TEI. Допущенный перевод создаётся текущей процедурой оформления редакторского решения. Чтение XML потоковое, распаковка ограничена 64 МиБ и не создаёт файлы по путям из tar. Декларации внутренних сущностей отклоняются.

В локальной разметке FreeDict 81 074 определения, 73 477 IPA и 5 894 других строки произношения. Для отдельной копии Kaikki на 5 000 написаний подготовлены 23 978 исходных глосс, 7 032 IPA, 3 073 помеченных варианта произношения, 10 280 грамматических характеристик и 8 стилистических помет. Примеры и их исходные связи сохранены в таблицах примеров. Разметка поддерживает явно атрибутированные регионы. В измеренных копиях регионов в V2 нет. Проверенного источника CEFR на уровне смысла пока нет. Отдельные элементы метаданных остаются pending и требуют разрешения на собственное свидетельство. Вложенное определение, показанное в CSV как контекст, сохраняется у исходного дочернего смысла. V2 экспортирует его только если этот смысл тоже пригоден к экспорту. Как отображать такой контекст в первой реальной статье, нужно согласовать до выпуска.

## Редакторский пилот и допуск

- В локальной папке `research/data/review/` созданы `enrichment_freedict_pilot_200.csv`, `enrichment_freedict_qa_96.jsonl` и `enrichment_freedict_ambiguities.csv`. Первый CSV предназначен для владельца. В нём 200 различных написаний с положительной наблюдаемой частотой, POS, переводом-кандидатом, английским контекстом, ID, локатором, источником, заявленной лицензией и объяснением отбора.
- Приоритет `standard` требует короткой русской фразы, единственного исходного кандидата, одного определения для контекста и известного POS. Квалификаторы, несколько вариантов и неясный контекст требуют специалиста. Ссылки на формы и пустое содержимое исключаются из очереди. Для контроля отобраны 96 задач по стратам «приоритет × POS × наличие контекста». Заголовки основного пилота исключены. Это контрольная выборка внутри того же источника, поэтому она измеряет качество процесса редактуры.
- Предложение для согласования. Случайно проверять минимум 96 отложенных задач независимым редактором, требовать отсутствия критических ошибок смысла, языка и происхождения. Страты с достаточным числом проверок должны показывать минимум 95% приемлемых кандидатов. Публиковать числитель и знаменатель отдельно для каждой страты. Малые страты требуют дополнительной проверки, а все спорные случаи повторно рассматривает человек. Порог служит решением о масштабировании очереди.
- Критерии допуска каждого переводимого смысла сохранены. Нужны явное человеческое решение, отдельные clearance статьи, смысла, исходного кандидата и редакторского перевода и постоянные ID статьи и смысла. Используются точные ключи staging. Пакетное применение откатывает весь несовместимый набор. Автоматическая классификация и выборочная статистика сами по себе статус допуска не меняют.

## Упаковка и производительность

Новый `package_format=2` хранит общий справочник политик и отдельные ссылки атрибуции. Идентификатор атрибуции, SQLite и её схема сохраняются. Валидация восстанавливает полную запись, сверяет её хэш и выполняет прежние проверки целостности, схемы, счётчиков и происхождения. Стандартный экспорт V1/V2 остаётся `package_format=1`. Компактный формат пока обслуживается только Python.

| Искусственных статей | SQLite, байт | Обычный манифест, байт | Обычный без отступов, байт | Компактный, байт |
| ---: | ---: | ---: | ---: | ---: |
| 5 000 | 4 919 296 | 10 506 320 | 8 806 154 | 2 166 478 |
| 20 000 | 19 222 528 | 42 076 328 | 35 276 162 | 8 716 486 |
| 100 000 | 98 295 808 | 210 556 336¹ | 176 556 170¹ | 43 756 494 |

¹ Сериализация восстановленного плоского манифеста в счётчик байтов без создания пакета. На 5 000 и 20 000 счётчик воспроизвёл размеры существующих плоских файлов. Воспроизводится опцией `enrichment_benchmark.py dictionary --flat-sizes`.

На 20 000 статей выигрыш около 79,3% от исходного формата и 75,3% от JSON без отступов. В обоих вариантах SHA-256 SQLite на 5 000 и 20 000 совпал. У искусственного набора одна политика, поэтому на разнообразных источниках эффект нужно измерять отдельно. Компактный пакет на 100 000 прошёл валидатор при действующем лимите 64 МиБ. Плоская кодировка на 100 000 выходит за лимит.

На Windows (Python 3.12.14, SQLite 3.53.1) полный импорт FreeDict с хэшированием, записью и проверкой целостности занял 279,4 с при параллельных локальных измерениях. Синтетическая сборка и проверка компактного пакета на 100 000 заняли 231,2 с в том же запуске. На 20 000 валидация занимала 5,38 с в плоском формате и 2,56 с в компактном. Пиковая память, отслеженная `tracemalloc` при отдельном повторе валидации, снизилась с 126 239 150 до 50 178 329 байт. Она учитывает только выделения Python.

Поиск измерен на SQLite запросами диапазона, объединения и группировки, с 29 повторами после первого запроса и лимитом 50 результатов. Искусственный широкий префикс совпадает со всеми заголовками в тестовой базе. Для 20 000 в компактном варианте p95 был 342,5 мс вперёд и 54,5 мс назад. На 100 000 p95 — 823,2 и 333,5 мс соответственно, валидация — 61,7 с. Планы использовали `entry_search`, `form_search` и `translation_search`. Широкий диапазон сохраняет стоимость группировки и сортировки. Результаты измерены при сопутствующей нагрузке и относятся к настольному SQLite, без выполнения Android-кода и отрисовки.

Искусственная личная база собрана из экспортированной схемы Room и содержит 10 000 сохранений, 100 подборок и 10 000 связей. SQLite занимает 1 073 152 байта, загрузка транзакции прошла за 0,105 с. p95 чтения всех сохранений 24,0 мс, списка подборок 0,48 мс, всех связей 9,06 мс, связей одной подборки 0,32 мс. Последний запрос использует покрывающий индекс составного ключа. Целостность и FK проверены. Память, задержка интерфейса и поведение Room на устройстве требуют отдельной проверки.

## Воспроизведение

Примеры команд рассчитаны на PowerShell из корня проекта с Python 3.10+. Используйте новые выходные пути, если локальные артефакты уже существуют. SQLite, архивы, реальные очереди и решения хранятся в игнорируемых каталогах.

```powershell
$poc = 'research/prototypes/sqlite_poc'
$interim = 'research/data/interim/corpus-enrichment'
$processed = 'research/data/processed'
$review = 'research/data/review'
$db = "$processed/enrichment_freedict.sqlite"
python "$poc/corpus_enrichment.py" import-freedict "$interim/freedict-eng-rus-2025.11.23.src.tar.xz" $db
python "$poc/corpus_enrichment.py" coverage $db
python "$poc/corpus_enrichment.py" pilot $db "$interim/subtlexus2.zip" "$review/enrichment_freedict_pilot_200.csv" "$review/enrichment_freedict_qa_96.jsonl"
python "$poc/corpus_enrichment.py" ambiguities $db "$review/enrichment_freedict_ambiguities.csv"
foreach ($n in 100,1000,5000) {
  python "$poc/run_import.py" $source "$processed/enrichment_frequency_$n.sqlite" --method frequency --frequency "$interim/subtlexus2.zip" --limit $n --seed 42
  python "$poc/corpus_enrichment.py" coverage "$processed/enrichment_frequency_$n.sqlite"
}
python "$poc/corpus_enrichment.py" kaikki-metadata "$processed/enrichment_frequency_5000.sqlite" "$processed/enrichment_kaikki_metadata.sqlite"
foreach ($n in 5000,20000,100000) {
  python "$poc/scale_fixture.py" "$processed/enrichment_compact_$n" --entries $n --compact
  python "$poc/enrichment_benchmark.py" dictionary "$processed/enrichment_compact_$n"
}
python "$poc/enrichment_benchmark.py" personal "$processed/enrichment_personal.sqlite"
python -m unittest discover -s $poc
```

`$source` — путь к прежнему локальному снимку Kaikki. Для замера пиковых выделений Python у отдельной команды `dictionary` используйте `--trace-memory`. При наличии локального файла WikDict одно направление можно проверить командой `python "$poc/wikdict_candidates.py" PATH.sqlite3 en-ru`. Для второго файла укажите `ru-en`.

После одобрения редактор переносит решения в JSONL по точным ключам `entry_id`, `sense_id`, `snapshot_sha256`, `locator`. Поля `classification`, `reason`, `proposed_translation` и `reviewer` заполняются по факту проверки. Статус `approved` и метод `human` формируются только по явному решению редактора. Отдельные файлы содержат права и постоянные ID.

```powershell
$release = "$poc/release_package.py"
$registry = "$processed/first_real_registry.sqlite"
python "$poc/review_queue.py" validate $db "$review/approved.jsonl"
python "$poc/review_queue.py" apply $db "$review/approved.jsonl"
python $release rights $db "$review/rights.jsonl"
python $release bind $registry "$review/bindings.jsonl"
python $release readiness $db --registry $registry
python $release export $db $registry "$processed/first_real_v2" first-real-v2 --schema-version 2
python $release validate "$processed/first_real_v2"
```

Команды выпуска выполняются только после необходимых решений. Из-за нулевого допуска реальный пакет не формировался. Первый запуск на Android и проверку широких запросов на контрольном устройстве следует провести после согласования данных.
