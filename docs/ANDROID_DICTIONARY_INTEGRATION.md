# Подготовка Android к подключению словаря

`DictionaryRepository` сейчас сообщает о наличии корпуса через `LocalDictionaryRepository`. `FoundationViewModel` использует этот результат для надписи в настройках. Для подключения будущий репозиторий должен различать доступную, отсутствующую, несовместимую и повреждённую базу.

1. Скопировать кандидат пакета в приватный временный каталог приложения. Проверить версию формата, SQLite `user_version`, нормализацию, SHA-256, обязательные таблицы и индексы, FK и целостность. При ошибке вернуть типизированный статус. Хранить последний проверенный пакет при неудачном обновлении.
2. Открывать словарный SQLite в read-only вне UI-потока. Нормализовать запрос согласованным алгоритмом, передавать параметры отдельно, ограничивать длину и выдачу. По постоянному ID загружать статью, её значения, переводы и атрибуцию. Для пустого и несовместимого корпуса возвращать состояние интерфейса с понятной причиной. Поиск и карточки после установки доступны офлайн.
3. После проверки нового снимка переключить ссылку на весь пакет и переоткрыть соединение. Личная Room-база хранится отдельно. При отсутствии постоянного ID новая версия не удаляет сохранённую пользователем подпись и историю.

Read-only SQLite позволяет задать собственный компактный формат и проверять его до открытия. Room удобен для типизированного чтения, но потребует совместимой предварительной схемы, identity hash и отдельной проверки миграций. Для личной изменяемой базы Room остаётся основным вариантом для рассмотрения. Выбор зависит от тестов на API 29 и новее. В частности, группировка с `row_number()` требует проверки версии SQLite или эквивалентного запроса для минимального API.

В `androidTest` добавлены две изолированные проверки. Первая создаёт временную искусственную базу, открывает её read-only, проверяет версию, целостность, связи и оконный запрос префикса. Вторая сравнивает выбранные Python-векторы с гипотезой Android ICU: NFC, полная регистровая свёртка ICU, повторная NFC, явный набор Python whitespace. Векторы охватывают ё, сигму, ß, апострофы, дефисы, дополнительную плоскость и запрещённые скаляры. Версии Unicode на разных устройствах могут менять результат. Полный прогон общей матрицы на минимальном и актуальном API остаётся условием включения Android-поиска.
