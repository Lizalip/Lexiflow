# Stage 1 · Решение о выпуске

LexiFlow проходит проверку как автономный двуязычный словарь. Переход к внешней поставке требует решения владельца о корпусе, лицензионной политике и порядке редакторской приёмки.

| Вариант | Результат | Объём проверки и решение владельца |
| --- | --- | --- |
| A. Индивидуальная проверка | Небольшой выпуск из явно разрешённых статей, значений, переводов и дополнительных полей | Редактор проверяет каждое включённое значение и цепочку источника. Владелец выбирает размер первого выпуска, подтверждает права и подписывает манифест. |
| B. Допуск по политике источника | Более широкий выпуск после структурной проверки всего корпуса, стратифицированной человеческой проверки и отдельного разбора исключений | Нужны решение владельца о допустимых источниках, целевой порог качества, правила повторной проверки и политика каталога атрибуций. Оценки с ИИ остаются подготовительными. |
| C. Внутренний Research | Локальная установка для индивидуальной курсовой работы и демонстрации владельцу | Сохраняются атрибуция каждого источника, локальное происхождение данных и отчёты. Нужна пользовательская приёмка. Выпуск APK с этим корпусом для распространения требует отдельного решения. |

Для FreeDict учитываются TEI-заголовки закреплённых пакетов и цепочка WikDict, DBnary и Wiktionary. CEFR-J требует атрибуции версии и автора. Tatoeba требует условий обеих сторон пары. Для аннотаций UD EWT хранится отдельная ссылка CC BY-SA 4.0. Условия объединения при распространении, формат титров и выполнение ShareAlike согласуются для конкретного выпуска. Производственный сборщик сохраняет существующий порядок допуска и отвергает исследовательские пакеты. [Источники и правообладатели](STAGE1_SOURCE_EVIDENCE.md)

Вариант C доступен на Samsung с 43 694 статьями, 1 696 грамматическими анализами из закреплённых dev и test UD English EWT r2.16 и 30 двуязычными парами Tatoeba. Эти формы описывают аннотации токенов с отдельными локаторами. Пары сохраняют лицензию обеих сторон. Варианты A и B ожидают решения владельца. Число производственных допусков — 0. ## Сохранение личных данных при переходе

Получить из исследовательского манифеста точные `kind`, SHA снимка и локатор. Найти ту же запись в одобренном staging, затем получить production UUID через действующий реестр identity binding. Сверить хеш исходного текста, POS и при необходимости локатор родителя. При изменении снимка требуется отдельная связь из журнала редакторских решений.

Предварительный список делится по фактическому результату сверки. Совпавшая запись получает двустороннее соответствие UUID. Изменившаяся запись сохраняет прежнюю локальную ссылку до ручного решения. Исчезнувшая запись остаётся в личной базе со своим заголовком и последним сохранённым текстом. Стратегия допускает обратимое разрешение алиасов к словарю при неизменных локальных ключах Room. Так заметки, переводы, подборки, карточки и история продолжают ссылаться на те же сохранения.

`research_identity_preview.py` демонстрирует сравнение точных ключей и хешей на синтетических данных. Он возвращает список соответствий без доступа к Room. Перед реальным переходом потребуются экспорт одобренного реестра, контроль обратимости и отдельная авторизация владельца.

## Короткая ручная приёмка Research

1. Открыть Research и сверить название активного корпуса. Найти `book`, открыть существительное и глагол, сверить различимые уровни CEFR.
2. В направлении RU → EN найти `мир` и `абрис`. Сравнить независимую русскую статью и обратные совпадения. Проверить `книга` как контроль обратного поиска.
3. В обогащённом пакете найти `went`, открыть базовую лемму и сверить метку формы. На запросе `thought` сверить приоритет исходной статьи и наличие формы `think`. Открыть `chance` и проверить несколько примеров с двумя ссылками атрибуции.
4. Сохранить одно значение, добавить собственный перевод и заметку, добавить запись в подборку, создать карточки обоих направлений и пройти одно повторение. Сверить изменение статистики.
5. Закрыть приложение, открыть снова и найти сохранённую запись. В отдельном ручном прогоне повторить поиск и карточку в физическом авиарежиме. Отдельно записать результат для английского офлайн-голоса, если он установлен.

Автоматические проверки обновления и отката проходили с тестовыми данными в отдельном профиле Samsung. Ручное тестирование требуется на рабочей установке и на устройстве с API 29. Если подходящий AVD уже установлен, запустить его из Android Studio Device Manager, сверить API через `adb shell getprop ro.build.version.sdk` и выполнить `gradlew.bat :app:connectedDebugAndroidTest` для выбранного тестового устройства. Установка образа согласуется отдельно.
