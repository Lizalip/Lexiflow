## Предложение к первому пилоту

Хранить одну проверенную политику источника на точный снимок и класс материалов. У каждой записи оставить ссылку на политику, исходный локатор смысла и поля для отличающихся авторских указаний и изменений. На первом шаге ограничить класс явными русскими переводами, у которых подтверждены точный английский смысл и происхождение. Требования к человеческой семантической редактуре, правам на конкретные элементы и устойчивым идентификаторам продолжают действовать. Компактный манифест уже объединяет повторяющиеся поля атрибуции. Пакетное применение общей политики требует отдельного решения и в текущем экспорте выключено.

| Материал | Действие перед включением |
| --- | --- |
| Заголовок, часть речи, смысл и исходный перевод | Сверить запись TEI, точный снимок, происхождение и возможные исключения. |
| Отредактированный перевод | Сохранить исходный текст, изменение, автора решения и отдельный локатор. Уточнить применимые условия адаптации. |
| Английская дефиниция и IPA | Проверить принадлежность узлу и происхождение каждого элемента. Для вложенной дефиниции отдельно подтвердить смысловую связь и права. |
| Пример употребления и перевод примера | Проверить источник, авторство и право распространения отдельно для двух текстов. Исключить внешние цитаты без достаточных свидетельств. |
| Аудио и изображения | Оставить за пределами первого пакета. Для будущего включения проверять страницу файла, автора и его условия. |
| Частотный отбор SUBTLEX-US | Использовать как локальный исследовательский сигнал. Веса и исходный список отсутствуют в пакете. |

До выпуска владелец определяет объём пилота, способ показа атрибуции, статус адаптированных переводов и правила исключения. Для неопределённых случаев нужна отдельная проверка применимых условий. Обнаруженных редакторских решений и допусков в проверенном staging — 0.

## Действия после получения решений

Работа ведётся с отдельной копией staging в `research/data/processed/` и явными файлами редактора в `research/data/review/`. Снимок исследования остаётся исходной точкой воспроизведения.

1. Запустить `review_queue.py validate`, затем `apply` с предоставленными семантическими решениями. Контекст при необходимости оформить отдельно через `release_package.py context`.
2. Передать отдельные документированные решения через `release_package.py rights`. Назначить устойчивые UUID через `bind` с сохранением существующего реестра.
3. Выполнить `release_package.py preflight STAGING SELECTION --registry REGISTRY`. `SELECTION` содержит только четыре исходных ключа в каждой строке JSONL. Проверить `ready == total`. Диагностика не меняет staging. Затем сверить счётчики `readiness`. Они учитывают одобренные переводы по всей копии staging, поэтому для ограниченного пилота применять решения только для согласованной выборки.
4. Выполнить `release_package.py export STAGING REGISTRY NEW_PACKAGE CORPUS_VERSION --schema-version 2 --compact`, затем `validate NEW_PACKAGE`. Сверить размеры двух файлов, количество статей и SHA-256 манифеста перед подготовкой APK. Новый каталог создаётся экспортёром.
