# План проверки Android-фундамента

## Автоматические проверки

Выполнять из корня проекта с JBR и Android SDK, описанными в [README](../README.md).

| Команда PowerShell | Проверяемое свойство | Свидетельство |
| --- | --- | --- |
| `.\gradlew.bat assembleDebug` | Компиляция, объединение ресурсов, упаковка | `app/build/outputs/apk/debug/app-debug.apk` |
| `.\gradlew.bat --gradle-user-home .gradle/verification testDebugUnitTest` | Начальное состояние без корпуса, маршруты и возвраты, черновик запроса и восстановление модели из копии значений SavedStateHandle | `app/build/test-results/testDebugUnitTest/TEST-app.lexiflow.ui.FoundationViewModelTest.xml` |
| `.\gradlew.bat lintDebug` | Статический анализ конфигурации, Java и ресурсов | `app/build/reports/lint-results-debug.html` |
| `.\gradlew.bat assembleDebugAndroidTest` | Компиляция и упаковка инструментальных тестов | `app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk` |
| `.\gradlew.bat connectedDebugAndroidTest` | Запуск пяти Espresso-сценариев | Требуется запущенный эмулятор или устройство с USB-отладкой |

### Покрытие и результат на 25 ноября 2026 года

В исходной ревизии было 3 JVM-теста и 1 инструментальный. Теперь 7 JVM-тестов проверяют старт без словаря, соответствие трёх разделов их вложенным экранам, смену вкладок с черновиком, возвраты из настроек и вложенных экранов, очистку запроса и восстановление маршрута и текста в новой модели. Проверка SavedStateHandle использует новый экземпляр с копией сохранённых значений.

Пять Espresso-сценариев:

1. Запустить приложение, проверить пустой словарь и переключиться между тремя вкладками.
2. Ввести смешанный текст и очистить его видимой кнопкой поля.
3. Открыть статью с введённым запросом, пересоздать Activity и вернуться стрелкой к исходному тексту.
4. Из повторения открыть прогресс и настройки, проверить статус базы и вернуться системной кнопкой через прогресс к повторению.
5. Открыть подборки, пересоздать Activity и вернуться в личный словарь.

Сборки обоих APK успешны, 7 из 7 JVM-тестов прошли, пропусков нет. Lint сообщил 0 ошибок и 1 предупреждение о версии Lifecycle. ADB не обнаружил устройств, поэтому `connectedDebugAndroidTest` пропущена. Поведение интерфейса в этих сценариях на устройстве пока не подтверждено. [Статус проекта](PROGRESS.md)

## Короткий ручной прогон в Android Studio

| Шаг | Ожидаемый результат |
| --- | --- |
| Запустить `app` в авиарежиме на Android 10+. | Открывается «Словарь», видны языковая пара, поле и сообщение о пустой базе. |
| Ввести смешанный текст с «ё», дефисом и апострофом. Открыть статью и вернуться стрелкой. Затем очистить поле. | Открывается пустая статья. После возврата текст сохраняется, кнопка очистки удаляет его. |
| Открыть «Мой словарь» → «Подборки», повернуть устройство и нажать системную кнопку «Назад». | Поворот сохраняет подборки, возврат открывает «Мой словарь». |
| Открыть «Повторение» → «Прогресс» → «Настройки», вернуться дважды. | Показаны пустые состояния и статус базы. Возврат проходит через прогресс к повторению. |
| Повернуть устройство при вводе, увеличить системный шрифт, открыть клавиатуру. | Запрос сохраняется, содержимое прокручивается, клавиатура и системные панели не перекрывают доступ к действиям. |

Для каждого прогона записать модель устройства или AVD, API, дату, результат шага и способ воспроизведения отклонения. Расширенная проверка включает TalkBack, жестовую навигацию и восстановление задачи после уничтожения фонового процесса. Эти сценарии остаются непроверенными.
