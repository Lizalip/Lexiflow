# Проверка лексики · Stage 1

## Исходная редакторская выборка

Проверены 280 уникальных значений из семи исходных страт, по 40 на страту. 619 строк перевода совпали с SQLite кандидата и с исходным staging FreeDict по точному локатору, снимку, статье, значению и тексту. Все записи имеют обоснование. В 14 ранних оценках отдельные поля неопределённости и действия отсутствуют, поэтому интерфейс оставляет их пустыми. Одобрений человеком 0.

| Наблюдение | Количество значений |
| --- | ---: |
| Предварительно правдоподобные | 139 |
| Проблемы или неопределённость высокой тяжести | 33 |
| Средней тяжести | 93 |
| Низкой тяжести | 15 |
| Контекст статьи содержит исходное определение | 275 |
| Статья содержит более одного значения | 184 |
| Значение содержит несколько переводов | 172 |
| Написание имеет не менее 10 000 вхождений в SUBTLEX-US | 73 |

Высокая тяжесть включает 17 сигналов смешения значений, 11 возможных расхождений POS, 4 возможных расхождения смысла и 1 нерешённое соответствие. Собственные определения источника показываются как контекст статьи. Сводка содержит группы по POS, страте, числу значений в статье, числу переводов, наличию определения и частоте. SUBTLEX-US указывает частоту написания, например для слова с несколькими значениями это общая частота. Страты намеренно смещены к задачам редактуры. Долю оценок нельзя переносить на весь корпус.

## Локальная редактура

В PowerShell из корня репозитория можно создать рабочую страницу так:

```powershell
python research/prototypes/sqlite_poc/research_editorial_audit.py `
  research/data/review/overnight-20000 `
  research/data/processed/research-scaling/bilingual-cefr-20000-marathon `
  research/data/processed/enrichment_freedict.sqlite `
  research/data/interim/corpus-enrichment/subtlexus2.zip `
  research/data/review/editorial-qa-rerun
```

Укажите новый выходной каталог. В нём будут `summary.json`, `queue.json` и `index.html`. В интерфейсе есть фильтры части речи, категории и тяжести. Строки упорядочены по тяжести и частоте, показывают текст, локаторы, контекст и предварительную оценку. Отложенные задачи сохраняются в файле сессии. При принятии формулировки или предложении отклонения с комментарием выгружается существующий формат JSONL со статусом `proposed`. UUID Research используются для чтения и проверки владельца. Ключи выгрузки берутся из точной строки staging FreeDict. Отдельное человеческое утверждение и лицензионный допуск по-прежнему необходимы.
## Межисточниковая проверка морфологии

До чтения кандидата выбран фиксированный набор из 150 связей «форма, лемма, POS, признак» из локального Kaikki staging. Выбрано по 30 связей на класс после отбора точного тега, исключения прежних контрольных связей и дубликатов. Порядок задан SHA-256 ключа. Сравнивались пилот с 15 анализами и действующий корпус с 1 696. Ожидаемые связи взяты из отдельного источника. Результат измеряет пересечение словарей и даёт очередь на просмотр, а точность требует независимой редакторской оценки.

| Класс | Пилот | Research RC | Написание формы также есть среди заголовков |
| --- | ---: | ---: | ---: |
| Герундий | 0/30 | 2/30 | 8 |
| Прошедшее время | 0/30 | 1/30 | 3 |
| Причастие прошедшего времени | 0/30 | 3/30 | 5 |
| Множественное число | 0/30 | 5/30 | 0 |
| Третье лицо единственного числа | 0/30 | 1/30 | 0 |

У Kaikki staging нет явной сравнимой разметки степеней сравнения в выбранных классах. Для них и для отрицательных контролей сохраняется отдельный набор из 24 английских связей и двух отрицательных запросов. Локаторы Kaikki сохранены в локальном CSV. Точную ревизию выгрузки Wiktionary ещё предстоит установить для решения об импорте. Парадигматический UniMorph даёт другой вариант для последующих сравнений, при этом требует маппинга тегов и согласования условий источника. [UniMorph English](https://github.com/unimorph/eng)

В действующих атрибуциях английских форм 1 070 записей относятся к dev UD EWT, 626 к test. В двух исходных срезах 3 110 токенов с UPOS AUX и 90 токенов с дефисом либо апострофом в целевых UPOS. Это число исходных токенов до проверки грамматических признаков. Для AUX и написаний с пунктуацией действующий экспорт сохраняет отдельные ограничения. [Данные и аннотации UD EWT](https://github.com/UniversalDependencies/UD_English-EWT/tree/r2.16)

Для воспроизведения передайте `--cross-source research/data/processed/enrichment_kaikki_metadata.sqlite` скрипту `research_morphology_evaluation.py` после выходного CSV и каталогов пакетов. CSV текущего прогона находится в `research/data/processed/research-scaling/jupyter/final-morphology-cross-source.csv`.
## Независимая выборка прямых статей RU–EN

Фиксированным хеш-порядком выбраны 113 значений разных написаний из установленной пары. Страты составили 3 академических, 10 деловых, 15 повседневных, 15 глагольных, 15 существительных, 15 прилагательных, 20 многозначных и 20 с несколькими эквивалентами. Академическая квота из десяти заполнилась частично. Частотный сигнал для отбора повседневных слов и глаголов взят только из dev UD Russian GSD. Для 71 значения есть контекст статьи, у 41 русского ключа есть также точный обратный результат. Совпадение ключа само по себе не подтверждает одинаковый смысл.

Все 113 оценок предварительные. 52 выглядят правдоподобными, 41 требует контекста, 13 показывают возможное смешение смыслов, 3 имеют проблемы представления, 2 слишком слабое или широкое соответствие, 2 требуют проверки POS. В числе замечаний смешение предметного и переносного значений, слитые английские эквиваленты и размеченные фрагменты в глоссах. Смысловая точность всего русского корпуса по этой выборке не оценивается. Оригинальная выборка из 280 значений сохранена.

## Проверка реального поиска

`research_search_ranking.py` компилирует действующий Java-планировщик `DictionarySearch` и передаёт его SQL и параметры в настольную SQLite. Метод использует нормализацию Python при подготовке ключей, поэтому не измеряет Android ICU или интерфейс. На SQLite нового кандидата совпали 25 из 35 ожидаемых целей. Два контрольных запроса с буквальными спецсимволами вернули пустой результат. Ни один ответ не повторил UUID значения и не превысил 50 строк.

В обоих запросах с коллизией формы и заголовка сохранён приоритет точного заголовка. Ожидаемая лемма по `spoken` заняла вторую позицию, по `thought` третью. Русские `деньги` и `город` дали прямой первый ответ, `встреча` дала только обратные совпадения. По `кухня` прямой ответ был первым, ожидаемый английский — пятым. Составная «ё» совпала с NFC-формой, а запрос с «е» вернул другие статьи. Среди пропусков — некоторые компьютерные термины, устойчивые выражения и нерегулярная форма множественного числа. Классификация пропусков и ранги сохранены в `research/data/processed/research-scaling/jupyter/final-android-sql-ranking.csv`.

CSV воспроизводится скриптом из двух локальных путей: каталога пары и свежего выходного файла. Также нужны аргументы `--jdk` и `--android-jar` для установленных JDK и SDK. Для оценки от ввода до видимого результата нужен отдельный Android-прогон. [Результаты стабильного Research](STAGE1_RESEARCH_RC.md)
