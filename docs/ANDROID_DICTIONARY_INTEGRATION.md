# Экспериментальный словарь Android

Словарный SQLite версий 1 и 2 открывает `LocalDictionaryRepository` в read-only. Debug при первом запуске предпочитает встроенный искусственный V2 и использует V1 при отсутствии V2. Для текущего тестового профиля перейти с встроенного V1 на встроенный V2 можно через настройки. Установка ограничивает объём записываемых данных и переключает указатель `AtomicFile` после проверки. При отклонении или прерывании чтения нового кандидата прежний пакет остаётся активным. Произвольная установка извне отсутствует в release.

Проверки включают версии формата и схемы, SHA-256 файла, число строк, целостность SQLite, внешние ключи, индексируемые колонки и ссылки на атрибуцию. Android пересчитывает поисковые ключи средствами ICU и отклоняет несовпадающий пакет. Эта проверка может занять больше времени на реальном корпусе. SHA-256 обеспечивает проверку совпадения файлов, а подлинность потребует доверенного канала поставки или подписи. Следующий этап должен проверить полные общие Unicode-векторы на API 29 и на актуальном Android.

Поиск выполняет диапазонные запросы по индексам статей, форм и переводов, группирует по идентификатору значения через `GROUP BY` и берёт не более 50 результатов. Запросы используют параметры. Порядок отдаёт приоритет точному совпадению. Оконные функции в Android-поиске отсутствуют. `FoundationViewModel` отложенно запускает поиск на одном рабочем потоке и сверяет поколение запроса перед доставкой. Маршрут, запрос, направление и выбранные идентификаторы сохраняются через `SavedStateHandle`.

## Совместимость контракта

V1 содержит статьи, POS, значения, переводы, формы, примеры, переводы примеров и происхождение. V2 добавляет отдельные определения, исходные глоссы, IPA, варианты произношения, регистр, регион, грамматику и CEFR. Отсутствующие поля не отображаются. Для экспериментальной озвучки кнопка появляется при доступном английском голосе, который движок помечает как установленный и локальный. Реальное воспроизведение без сети предстоит проверить на устройстве.

Поиск ограничивает выдачу до загрузки предварительного перевода и совпавшей формы. V2 добавляет индекс перевода по смыслу и индексы родительских связей форм и примеров. Широкий префикс по-прежнему требует группировки кандидатов перед LIMIT. На каждый экземпляр репозитория выполняется одна попытка начального открытия. Словарные ключи проверяются при открытии и установке, поэтому стоимость первого запуска на большом корпусе предстоит измерить.

Сборщик использует Java 17 и обычный desugaring D8 для языковых конструкций. Для коллекций используются `Collections` и `Arrays`. Android добавил фабрики `List.of` и `Set.of` в API 30. Ввод читается ограниченным циклом через `InputStream`. Поиск использует CTE и GROUP BY без оконных функций. Совместимость ICU, SQLite и установщика на API 29 требует прогона на устройстве. [Android и desugaring](https://developer.android.com/studio/write/java8-support) · [Android ICU](https://developer.android.com/reference/android/icu/lang/UCharacter) · [List](https://developer.android.com/reference/java/util/List) · [Set](https://developer.android.com/reference/java/util/Set)

SQLite read-only позволяет проверять поставляемую схему отдельно от приложения. Room применяется для локальных пользовательских данных. Использование Room для словарного снимка потребует совпадения схемы и Room identity hash при поставке. Окончательный формат словаря остаётся открытым.
